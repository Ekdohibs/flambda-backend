# X5: the compiler's own run as a second mode of the test tool

## Done

- `middle_end/flambda2/tests/tools/ownrun/flsemantics_ownrun.ml`: the driver of
  the compiler with the hooks `Raw_flambda2` and `Flambda2` registered,
  which gives the two terms of the compiler's own run to
  `Flsemantics.check`. It takes the compiler's command line, prints
  what the tool prints, and exits 1 where the check failed. It is in a
  directory of its own and is built in the main context only, as it
  needs the library `unix`; the modules of the check are copied there.
  Since V2 mended it, the first hook keeps the term and asks nothing,
  and the check is made in a child process when Simplify has returned.
- `middle_end/flambda2/tests/semantics/ocaml/own_run.sh`: the command
  that gives a unit to the driver, in a directory of its own.
- `middle_end/flambda2/tests/semantics/own_run/`: a control of the
  driver given two units in one process, the first in the classic mode.

## The rules, which are V2's

`middle_end/flambda2/tests/semantics/ocaml/README.md`, "The compiler's
own run", says what the second way is, what the rules compare and what
they do not cover. Under "The rule" it names each unit that the rules
do not compare in the ordinary way, with the reason. In short:

- In the main context the rules of that directory (`gen_rules.sh`) run
  the driver on every unit that the directory itself holds, and compare
  what it prints with `X.expected`, the file that what the tool prints
  of the text is compared with. In the ordinary way `own_same.sh` asks
  that the two be the same bytes.
- Of a unit that `own_run_numbers.txt` names, each file must be one
  line of the form that `own_same.sh` accepts; it compares the two
  lines up to the number and the mark of each word that it takes for a
  variable.
- A unit that has `X.own_expected` is compared with that file in the
  place of `X.expected`. It is for a unit of which the two ways are
  known not to print the same: of such a unit the rule shows that the
  driver prints what that file has, and nothing of an agreement of the
  two ways.
- Of a unit that `tool_fails.txt` names the rules take the status 1
  from the driver, and no other; of any other unit, the status 0 and
  no other.

## Measured with the driver as it first was

This count was made with the driver as its first series brought it,
before the driver was mended and before the rules above. It is kept as
what was found then.

At the default flags, of the 347 units of `tests/semantics/ocaml/` at
87cdbf3e01: 242 print "validated" (22 of them with their imports; one
of the 242 is `empty_array_phys_equal.ml`, whose run is undefined in
the model, so 241 of the 325 that the tables of the README count), 86
not checked (82 at a `Make_block` whose fields have a kind that is not
any value), 16 not validated, 3 whose term after is not well-formed
(the driver exits 1).

## What that count had open, and what became of it

- The first way validated 78 units that the second did not check: the
  conversion refused a `Make_block` whose fields have a subkind or are
  never null, which the terms in memory have and the text has not. The
  rules now ask that the two ways print the same of every unit but
  those that the README names, as said above.
- `div_unknown.ml`, `string_get16_checked.ml` and
  `string_get_twice.ml`: the compiler's own term after was refused as
  not well-formed (discrepancy X5-9), and the driver exited 1 on them.
  Since decision D60 both ways validate each of the three with its
  imports (the README above, "What a validation does not say").
- `string_get_in_branch.ml`, `string_get_two_indices.ml` and
  `string_length_after_join.ml` were validated in the first way and not
  in the second. Both ways now print the same of each, "validated with
  its imports".

## Open

- `pairs/` and `library/` of
  `middle_end/flambda2/tests/semantics/ocaml/`: no rule runs the driver
  on them. `own_run.sh` compiles one unit in a directory that has
  nothing else and gives `-nostdlib`; the second unit of a pair needs
  the `.cmx` file of the first, and a unit of `library/` the standard
  library.
- The rules are at the default flags.
